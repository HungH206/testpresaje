# LiveKit camera testing

The website publishes camera video to LiveKit Cloud. A persistent worker
subscribes, decodes frames, runs SmartSpectra, and publishes results back to the
room. The phone and dashboard can use Vercel HTTPS, while production processing
runs from a normal Node process on your Mac or VPS. No Cloudflare tunnel or
browser frame-upload endpoint is used by this workflow.

## Configuration

Use Node 24 LTS (the installed LiveKit dependency tree requires Node >=22.22).
Create a LiveKit Cloud project at https://cloud.livekit.io and obtain its project
URL and API credentials. Add these values to your local `.env`:

```dotenv
LIVEKIT_URL=wss://your-project.livekit.cloud
LIVEKIT_API_KEY=your_livekit_api_key
LIVEKIT_API_SECRET=your_livekit_api_secret
LIVEKIT_ACCESS_CODE=a-long-random-test-access-code
LIVEKIT_ROOM=vitalscan-test
SMARTSPECTRA_API_KEY=your_presage_key
SMARTSPECTRA_METRIC_MODE=baseline
```

Set the same five LIVEKIT variables in Vercel, then redeploy with the build
command `npm run build`. Set `SMARTSPECTRA_API_KEY` only on the worker host,
not in browser code.
Never put API secrets in browser JavaScript or in a URL.

This is a shared, single-scan test room. Everyone with the test access code can
join and receive results. Use a random code, share only with your testers, and
rotate it after testing. The token endpoint issues short-lived, room-scoped
tokens; it never issues processor credentials to browsers. Production needs
user authentication and isolated rooms/workers per scan.

## Run the worker

```sh
npm install
npm run worker
```

Keep the worker running on your Mac. In another terminal, `npm run dev` serves
the local dashboard, or use the deployed Vercel site on both devices.

For a VPS deployment, clone the repo on the server, create `.env`, install
dependencies, then run the worker under PM2:

```sh
npm ci
pm2 start npm --name vitalscan-worker -- run worker
pm2 save
```

The worker host needs:

```dotenv
LIVEKIT_URL=wss://your-project.livekit.cloud
LIVEKIT_API_KEY=your_livekit_api_key
LIVEKIT_API_SECRET=your_livekit_api_secret
LIVEKIT_ACCESS_CODE=a-long-random-test-access-code
LIVEKIT_ROOM=vitalscan-test
SMARTSPECTRA_API_KEY=your_presage_key
SMARTSPECTRA_METRIC_MODE=baseline
```

Use Node 24. `package.json` pins the app to Node 24.x.

On the dashboard, enter the test access code, select **Use Phone Camera**, and
click **Connect Dashboard**. Enter your deployed website URL in the address
field. Open the generated `?capture=phone` link on the iPhone, enter the same
code, then tap **Start Scan** and grant camera permission.

**Use Mac Camera** uses the Mac browser camera through LiveKit. The explicit
`http://localhost:3000/?camera=server` route retains the direct native camera
diagnostic path. Do not run that scan or `test:cardio` concurrently with a worker
scan.

## Verification and limits

- Capture FPS counts frames presented to the phone video element, using
  `requestVideoFrameCallback`; it is not a sensor-level FPS measurement.
- Received FPS counts decoded frames delivered to the processor.
- Accepted FPS counts frames accepted by SmartSpectra.
- The worker preserves decoded-media timestamps and handles rotation without
  stretching. These are LiveKit media timestamps, not a claim of exact sensor
  exposure timestamps. Duplicate/non-increasing timestamps are dropped.
- The camera requests 30 fps, H.264, no simulcast, and a 4 Mbit/s encoding cap.
  These are requests, not guarantees of delivered quality or frame rate.
- Compression and network loss can still affect physiological measurements.
  Compare against native-camera tests before relying on scan results.
- This initial CSP allows LiveKit Cloud domains. A self-hosted LiveKit server
  requires updating `connect-src` in `public/index.html`.

The browser bundle is generated by `npm run build` and excluded from git.
Run `npm test` and `node --test scripts/*.test.js` for local checks.
